# Sheets: Development Plan

A single-page web app, deployed to GitHub Pages by GitHub Actions, for editing and
previewing calculation-oriented text documents. The whole document state lives in
the URL. Saving to and loading from HashBin is optional. Users can edit source, look
at the rendered document, or show only one of the two. Header links lead to
documentation and an example gallery.

[ManimOnline](https://github.com/curtcox/ManimOnline) is the reference for
structure and conventions: buildless static site, ACE editor, URL sharing, HashBin
client, gallery, Node unit tests, and Playwright browser tests in CI. This project
supports a different set of formats.

## Implementation status

Phases 0–10 are implemented and deployed on GitHub Pages, with the supported
subsets and compatibility gaps recorded in the format guides. Source downloads,
standalone rendered HTML exports, preview printing/PDF, and dedicated ACE modes
for Beancount, Org, Numbat, and Hurmet are also implemented. All 36 gallery
examples have static previews regenerated by `npm run gallery:covers`. Optional
offline access caches verified app assets, the eight vendored engines, docs,
and examples; Python, R, and external services still require a connection.
Calca now solves real scalar linear and quadratic equations, including reverse
definitions and multiple real roots, with bounds and explicit subset diagnostics.
Quarto R cells run through pinned webR 0.6.0, with state, console output, PNG plots,
cell diagnostics, cancellation and deadlines. All items in the original phases
0–10, including the optional offline and equation/R execution work, are implemented.
The compatibility roadmap below has started: the baseline disclosure ledger and
profile design are in place, and the first Beancount decimal/tolerance work is
implemented. Further auditing and compatibility features remain open.
HashBin is registered and enabled using its public client ID and exact Pages
callback. Live PKCE authorization, quoted save confirmation, and an anonymous
saved-document round-trip have been verified. The repository uses MIT and Pages
deployment is enabled through GitHub Actions.

## Decisions

| Topic | Decision |
|---|---|
| Build | **Buildless.** No bundler at deploy time. Native ES modules in `src/`. Third-party code is vendored under `vendor/` at pinned versions. A library that only ships as source (Numbat, CalcFile, Hurmet) is built once by a script in `scripts/vendor/`, and the output is committed. |
| Editor | ACE, vendored, as in ManimOnline. |
| Math rendering | [Temml](https://temml.org) (MIT; TeX to MathML). Shared by GFM, AsciiMath, Quarto and Calca. Hurmet bundles its own copy. |
| Sanitizing | All rendered HTML goes through DOMPurify. Anyone can craft a shared URL, so treat every document as untrusted input. |
| Heavy engines | Numbat, Hurmet, Python and R run in Web Workers, with a timeout and cancellation (terminate the worker). Stale results are discarded by revision number. |
| Beancount | Own permissively licensed JS engine for a core subset. (@rustledger/wasm is GPL-3.0, and Python Beancount needs C/C++ extensions that Pyodide does not provide.) |
| Quarto | Markdown plus `{python}` cells run with Pyodide and `{r}` cells with webR. OJS and Julia cells are shown but not executed. |
| CalcFile | [peetzweg/calcfile](https://github.com/peetzweg/calcfile) v0.1 draft (Apache-2.0). Pin a commit, because the format is pre-1.0. |
| Format order | Easiest first: GFM, AsciiMath, Numbat, CalcFile, Org tables, Calca, Hurmet, Beancount, Quarto. |

### Format plugin contract

```js
export default {
  id: 'numbat',                    // used in the URL and in HashBin documents
  label: 'Numbat',
  extensions: ['.nbt'],
  aceMode: 'ace/mode/text',
  detect(src) { return 0..1 },     // confidence; only used by Auto
  async load() { /* import engine, start worker */ },
  async render(src, { signal }) { return { html, diagnostics: [{ line, message }] } },
  docs: 'docs/formats/numbat.md',
};
```

Engines are kept free of DOM code so `node --test` can import and test them
directly. `render` returns HTML that the shell sanitizes and puts in the preview.
Diagnostics show up as ACE gutter annotations and in a status bar.

### URL state

ManimOnline's parameter names are kept so its share-link and HashBin code ports
with minimal changes:

- `?format=<id>` sets the format. If it is missing, Auto detection picks one.
- `?view=split|source|preview` sets the view. Split is the default.
- `?compressed=<lz-string>` holds the source.
- `#<cid>` loads the document from HashBin.
- `?example=<id>` loads a gallery example once. The source is then stored in `compressed`.

The URL is updated with `history.replaceState`, debounced, so typing does not fill
up browser history. When the URL gets longer than roughly 8 KB, the status bar
suggests saving to HashBin.

### HashBin document

```json
{ "format": "sheets-document", "version": 1, "type": "<format id>", "src": "...", "view": "split" }
```

Plain-text payloads also load, and in that case Auto detection picks the format.
Accepted link hosts are hashbin.org, 256t.us and curtcox.github.io.

## Phase 0: Deploy to GitHub Pages

Goal: a page at <https://curtcox.github.io/sheets/> deployed by Actions on every push to `main`.

1. In the repository's **Settings → Pages**, set Source to **GitHub Actions**
   (or run `gh api -X POST repos/curtcox/sheets/pages -f build_type=workflow`).
2. Add `.github/workflows/deploy.yml`, based on ManimOnline's: checkout, configure-pages,
   upload-pages-artifact, deploy-pages, with `pages: write` and `id-token: write`.
   The only change from ManimOnline is a staging step that copies only the served
   files (`index.html gallery.html docs.html docs src vendor examples .nojekyll`)
   into `_site/`. That way `tests/` and `scripts/` are not published.
3. Add a minimal `index.html` containing the toolbar skeleton, a `<textarea>`, a preview
   that shows escaped text, and a footer with the commit SHA. Add `.nojekyll`.
4. Add a post-deploy step that fetches `page_url` and checks for a marker string, so a
   broken deploy fails the workflow.
5. Add `test.yml` (runs on push and PR): `node --check` on all scripts and `node --test`.
   Make deploy depend on tests passing.

Done when: pushing to `main` updates the live page, and the workflow fails if the deployed page is wrong.

## Phase 1: Editor shell

Everything except the formats themselves, tested with a built-in plain-text format.

1. **Layout and editor.** Vendor ACE. Add the toolbar (format selector with Auto, view
   toggle, Share, HashBin, Docs, Gallery) and a resizable split.
2. **View modes.** Split, Source only and Preview only. Buttons plus keyboard shortcuts.
   The view is stored in `?view=`. Below 760 px the panes stack vertically, and the
   toggle switches between them.
3. **URL state.** Implement `url-state.js` as described above. Unit tests cover round-trips,
   precedence (`#cid` over `?compressed` over `?example`) and removing old parameters.
4. **Render scheduler.** 300 ms debounce, revision counter, `AbortSignal` passed to
   `render`, and a status bar showing rendering, error or done.
5. **Format registry.** Lazy `load()`, Auto detection (highest confidence above a
   threshold, otherwise GFM), and a manual override that is stored in the URL.
6. **HashBin.** Port `hashbin.js` and `hashbin-panel.js` from ManimOnline and change the
   document format. Register a HashBin app for `https://curtcox.github.io/sheets/` and put
   its public client ID in a `<meta name="hashbin-client-id">` tag. Loading public CIDs
   works without registration. Saving needs it.
7. **Share.** Copy-link button and optional is.gd shortening, ported from `share-links.js`.
8. **Docs and gallery skeleton.** `docs.html` renders `docs/*.md`. Until Phase 2 lands it
   shows them as preformatted text. `gallery.html` reads `examples/catalog.json`, with
   cards, search and a format filter. Each card has a **Load in editor** link
   (`index.html?example=<id>`).
9. **Browser tests.** Port the Playwright setup: editing updates the URL, reload restores
   the state, view modes work, and examples load. Run on chromium, firefox and webkit.

Done when: a shared link reproduces source, format and view in another browser, and HashBin save and load round-trip.

## Phases 2–10: one format at a time

Every format phase must deliver all of the following:

- an engine in `src/formats/<id>/`, plus vendored dependencies with entries in `vendor/README.md`
- `detect()` with unit tests, including tests that it does *not* claim other formats' examples
- at least four gallery examples covering basic, typical, edge and error cases
- `docs/formats/<id>.md`: what the format is, the supported subset, known gaps, and upstream links
- unit tests against fixtures, plus a browser test that renders every gallery example for that format
- a HashBin round-trip test that keeps the format

### Phase 2: GitHub Flavored Markdown

- **Engine:** markdown-it plus plugins for task lists, footnotes and GitHub alerts
  (`> [!NOTE]`). Tables, strikethrough and autolinks are built in. Code is highlighted
  with highlight.js. `$…$` and `$$…$$` and ```` ```math ```` blocks render with Temml,
  as GitHub does. Mermaid is loaded lazily, and only if a ```` ```mermaid ```` block is present.
- **Conformance:** run the GFM spec examples from `github/cmark-gfm`'s `spec.txt`.
  Record the pass rate and list known deviations in the docs. markdown-it is close to
  GFM but not exact.
- **Shared output:** the GFM pipeline (`renderMarkdown(src, { math })`) is reused for
  prose in AsciiMath, Calca and Quarto, and for `docs.html`.
- **Detection:** this is the fallback format, with low confidence.

### Phase 3: AsciiMath

- **Engine:** asciimath2tex (Apache-2.0), then Temml.
- **Document model:** GFM prose where `$…$` and `$$…$$` are read as AsciiMath instead of
  TeX, plus ```` ```asciimath ```` fenced blocks. A file with no Markdown structure is
  treated as one display formula per line.
- **Extras:** a "Show TeX" toggle under each formula, to help with debugging and learning.
- **Detection:** AsciiMath fences, or a high share of AsciiMath-only tokens such as
  `sum_(i=1)^n` or `sqrt` without a backslash.

### Phase 4: Numbat

- **Vendor:** `scripts/vendor/numbat.sh` checks out `sharkdp/numbat` at a pinned tag
  (currently v1.24.0) and runs `numbat-wasm/build.sh` (`wasm-pack --target web`).
  The script commits `vendor/numbat@<ver>/` (pkg JS + `.wasm`). Dual MIT/Apache-2.0.
- **Engine:** runs in a worker. `new Numbat(true, true, FormatType.Html)`, then
  `interpret()` on the document one statement at a time in a single context. Each
  statement gets one result row, shown beside its line. Errors attach to their line.
- **Exchange rates:** fetch the ECB XML, call `set_exchange_rates`, and cache the result.
  If the fetch fails, show a notice and leave currency units without rates.
- **Detection:** `let`, `fn`, `->` conversions, or `unit` / `dimension` declarations.

### Phase 5: CalcFile

- **Vendor:** `scripts/vendor/calcfile.sh` checks out `peetzweg/calcfile` at a pinned commit.
  It uses esbuild to bundle `packages/core/src/index.ts` (and mathjs) into one ES module,
  `vendor/calcfile@<sha>/core.mjs`, and copies `fixtures/conformance/calcfile-v0.1.json`.
  (`packages/core` is private and not on npm.) This is a one-time vendoring step; the
  site itself stays buildless.
- **Engine:** `evaluateDocument()`, with results shown beside lines the way CalcFile Web
  shows them. Text, header and comment lines are styled by `LineKind`.
- **Conformance:** run all v0.1 conformance cases in `node --test` (37 required ones as of today).
- **Detection:** low. CalcFile looks like prose with numbers. Pick it through
  `?format=calcfile` or the `.calc` extension when loading HashBin plain text.

### Phase 6: Org-mode tables

- **Engine:** own code. orga (MIT) parses the surrounding Org structure (headings,
  lists, emphasis, links). A new evaluator handles tables and `#+TBLFM:`.
- **Formula subset:** column (`$3=$1*$2`) and field (`@2$3=`) formulas; references
  `@<` `@>` `$<` `$>`, relative `@-1`, hline `@I`/`@II`; ranges `@2$1..@>$1`;
  `vsum vmean vmin vmax vcount vprod`, arithmetic and common Calc functions; format
  specifiers `;%.2f`; and modes `;N`. `'(elisp)` formulas show an "unsupported" diagnostic.
- **Output:** the recalculated table, plus a **Copy recalculated source** button that
  works like `C-c C-c` in Emacs.
- **Fixtures:** `scripts/org-expected.sh` runs `emacs --batch` with
  `org-table-recalculate-buffer-tables` to produce expected outputs. The test workflow
  installs `emacs-nox` and checks that the committed expected outputs still match.
- **Detection:** `#+TBLFM:`, `|---+` hlines, or `#+TITLE:`-style keywords.

### Phase 7: Calca

- **Risk:** Calca is a closed commercial app with no published spec, so the target is
  the behavior shown in Calca's documentation and examples. The docs page will say
  "Calca-compatible subset". Check atom-calca (MIT) as prior art.
- **Engine:** GFM for prose. Calculation lines are code blocks (indented or fenced) or
  lines containing `=>`. mathjs handles numbers, variables, user functions
  `f(x) = x^2`, units and conversions (`in`), and matrices. Results replace the text after
  `=>`. Symbolic results are partial: mathjs `simplify` and `derivative` cover simple
  cases. Numeric scalar linear/quadratic equation solving is implemented as a
  bounded subset; symbolic answers and general systems remain unsupported.
- **Detection:** lines matching `… => …`.

### Phase 8: Hurmet

- **Vendor:** `scripts/vendor/hurmet.sh` checks out `ronkok/Hurmet` at a pinned commit and
  runs its rollup config on `src/hurmet.js` with `format: "es"` instead of CJS. It
  commits the bundle (about 1.3 MB, loaded lazily) and Hurmet's CSS. MIT license.
- **Engine:** compute the calculation cells (as `updateAndSave` does), then `md2html`.
  Supports `¢ … ¢` calculations, units, and spreadsheet tables.
- **Currency rates:** fill `globalThis.currencyRates` from the same cached ECB fetch used by Numbat.
- **Detection:** `¢` calculation delimiters.

### Phase 9: Beancount

- **Engine:** own JS code, MIT-licensed. Directives: `option`, `open`, `close`,
  `commodity`, transactions (`*`/`!`/`txn`) with postings, inferring one missing amount,
  tags, links and metadata; `balance`, `pad`, `price`, `note`, `event`. `include` and
  plugins are reported as unsupported. Inventories are per account and commodity, with
  simple `{cost}` lots. Lot-matching rules beyond FIFO come later.
- **Reports in the preview:** errors (unbalanced transactions, failed balance
  assertions, postings to closed accounts), balance sheet, income statement, trial
  balance, and a per-account journal. Reports come from tabs inside the preview.
- **Fixtures:** the test workflow runs `pip install beancount` and checks that the
  committed expected outputs still match `bean-check` and `bean-query` results for each fixture.
- **Detection:** lines matching `^\d{4}-\d{2}-\d{2} (open|close|balance|price|\*|!|txn)`.

### Phase 10: Quarto

- **Engine:** js-yaml (front matter: `title`, `author`, `date`, `execute`). The document
  is split into prose and executable cells. Prose uses the GFM pipeline plus Pandoc-style
  fenced divs (`::: {.callout-note}`), `{#fig-…}` labels with basic `@fig-…` cross-references, and Temml math.
- **Python:** Pyodide (pinned version, loaded from jsDelivr on first use) runs in a
  worker. All cells share one interpreter, so state carries over. Cell options are read
  from `#|` lines (`echo`, `eval`, `output`, `label`, `fig-cap`). Output can be stdout,
  the repr of the last expression, a DataFrame `_repr_html_`, or a matplotlib figure
  as SVG. Packages imported by the cells load through `pyodide.loadPackagesFromImports`.
  Cells rerun after edits are debounced, the worker is terminated on cancel, and there
  is a 90-second deadline.
- **R:** webR 0.6.0 loads lazily from its pinned CDN URL. R cells share a fresh
  interpreter per render, separately from Python. Console output, visible values,
  warnings/messages and base graphics PNG plots are captured. Errors stay with
  their cells and later cells continue. Cell/front-matter options apply to both
  languages. PostMessage works without special Pages headers. Cancellation and
  the 90-second deadline close the R interpreter worker directly.
- **Other languages:** `{ojs}` and `{julia}` cells are shown with a "not executed
  in the browser" note.
- **Detection:** YAML front matter with Quarto keys, or executable cells, including ```` ```{python} ```` and ```` ```{r} ````.

## Compatibility roadmap: prioritize and eliminate limitations

Status: **in progress**, refreshed 2026-10-19 after `78a0616`.
This roadmap extends the completed original plan; future capabilities remain open.
The verified baseline before ORG-1A is 272 unit tests, 219 browser tests, 37 required
CalcFile cases, and 672/672 canonical GFM examples (601/672 production HTML,
with presentation/sanitization differences classified). The shared ledger has
59 disclosures. The function comparison page now distinguishes callable libraries,
custom definitions, imported packages, and display-only notation. The original
inventory at `d99cb58` is retained in the baseline disclosure fields.

First increment: `docs/compatibility.json` imports the existing disclosures with
stable IDs, priorities, classifications, audit status, and evidence fields.
`scripts/compatibility-docs.mjs` generates the central page and guide status tables;
unit tests reject drift. Compound entries without atomic reproducers remain
explicitly marked for detailed audit, so Phase 11 is not complete.
`design/compatibility-profiles.md` records the migration contract without changing
URL or HashBin behavior. The Beancount oracle now preserves decimal strings, with
22 independent fixtures covering supported arithmetic/tolerance behavior, including
large/tiny amounts, costs/prices, inference, assertions, padding, and lots. BEAN-1's
first slice implements decimal arithmetic, supported tolerance options, and exact
report text. Other booking/rounding options and wider audits remain open.

Second increment: CALCA-1 introduces a parsed Markdown document model and the
explicit `calca-blocks-v1` profile. Structured blocks isolate literal fences,
inline code/math, TeX, Mermaid, headings, links, and HTML from calculation input;
supported Calca fences, indented blocks, and paragraph arrow expressions retain
source locations and document order, including footnotes. Unprofiled URLs and
version-1 HashBin documents keep the original renderer. Profiles now round-trip
through URLs, version-2 envelopes, sharing, OAuth snapshots, view changes,
and offline reloads. Source downloads keep text alone and disclose the need to
select the profile when reusing it. The profile contract
has executable migration cases; the broader Phase 11 atomic audit remains open.
Third increment: CALCA-2 adds `calca-scopes-v1` (Scoped definitions) while keeping
Legacy and Structured blocks semantics unchanged. First visible definitions are
immutable, repeated definitions become constraints, and definitions/relations are
available within their heading and descendants. Deferred numeric dependencies and
function free variables use query-visible bindings. Candidate real scalar roots
are checked against connected relations; contradictions and unsupported systems
report diagnostics. Cycles, depth, statement count and evaluation work are bounded.
The published parent/child/sibling example has an attributed reference fixture;
child redefinition, deferred binding, conflict presentation and Setext support are
explicit project policies pending licensed-app comparison (CALCA-04). The gallery,
docs editor links, URL/HashBin envelopes, OAuth and offline tests cover the profile.
An indirect built-in function-value guard bypass is closed for all shared math
users. Calca still evaluates one line at a time; CALCA-3's input grammar, symbolic
answers, function inversion and general systems remain future work.

Fourth increment: CF-1 connects CalcFile's actual missing-external-data diagnostics
to the shared ECB service. The official data API supplies a CORS-readable decimal
CSV; a validated daily XML snapshot retains existing Numbat/cache interfaces and
excludes discontinued older series. Decimal rate lexemes and publication dates reach the
pinned engine unchanged, enabling EUR ↔ USD/GBP/JPY. Requests are skipped for
same-currency arithmetic/conversion, prose, comments and ordinary unit conversion.
The cache validates daily-feed structure, positive rates, dates and timestamps;
stale/offline fallback retains its original date and shows a notice. Cancellations
do not render or cache late responses. Source links and saved documents retain
source, not rate snapshots. The pinned engine's EUR-base pair and four-currency
boundaries remain disclosed under CF-05. The original 37 conformance cases remain
unchanged. Shared-consumer coverage also found and fixed Hurmet's numeric-rate
bridge: its rational parser now receives decimal strings instead of numbers.

### Goal and prioritization

Close gaps that change results first, then widely used missing capabilities, then
larger language and runtime features. Within a priority, prefer changes that reuse
an existing engine or benefit several formats. Effort labels are relative:
**S** is a bounded adapter change, **M** changes a subsystem, and **L** introduces
a language/runtime or architectural boundary. These are scope estimates, not
delivery dates; re-estimate after the first reference fixtures.

The limitations page mixes four kinds of entries. Classify them before counting
progress:

| Kind | Treatment |
| --- | --- |
| Implementation defect or missing upstream behavior | Add a reproducer and implement a verified fix. |
| Upstream behavior or format purpose | Retain and explain it. Reserved unit names, dimensional errors, and non-executable Markdown/AsciiMath/plain text are not missing evaluators. |
| Deliberate safety or reproducibility policy | Preserve the default. Add a bounded, explicit alternative only when useful; do not remove sanitization, cancellation, payload bounds, or interpreter isolation to claim parity. |
| Browser or deployment constraint | First test a browser implementation; otherwise provide an optional native execution route with an explicit architecture decision. Do not label an unimplemented route as resolved. |

### Phase 11 — P0: establish a complete compatibility backlog (M)

1. Give every limitation an ID, format, upstream version/reference, smallest
   reproducer, expected behavior, current behavior, priority, dependencies, and
   disposition. Split compound disclosures into independently closable items.
2. Audit upstream examples as well as the present inventory. In particular, check
   Calca's named/multiline definitions, argument binding, indexing/ranges, local
   definitions, locale handling, and symbolic behavior. The current list is not an
   exhaustive specification of the original applications.
3. Pin the compatibility targets. Keep the existing GFM corpus, CalcFile draft,
   and Numbat/Hurmet revisions initially. Use the pinned Beancount/bean-query and
   Emacs reference tools for new fixtures. For Calca, use public reference examples
   and clearly identify cases that still require verification in a licensed app.
4. Make one structured limitation ledger drive the central page and guide
   disclosures, with links to fixtures and status. Keep prose explanations in the
   guides, but check them against the ledger so resolved gaps cannot remain stale.
5. Define behavior versioning before changing established semantics. Old source
   links and version-1 HashBin documents must retain their documented behavior;
   record a compatibility profile in new links/envelopes when behavior changes,
   with explicit migration rather than silent reinterpretation.
   Profiles preserve intentional language semantics, not known incorrect
   arithmetic. Numeric correctness fixes apply to supported documents with
   reference-backed result comparisons and release notes; original source remains
   intact.

Done when: every existing disclosure has a disposition and work item; newly found
gaps are recorded; the reference baseline is reproducible; and the profile/migration
design has fixtures for old URLs and saved documents. This is an enabling milestone,
not permission to postpone known correctness fixes indefinitely.

### Phase 15 — P2/P3: remove browser-shell and execution restrictions

1. **QT-2 — notebook outputs and controls (M):** add figure dimensions/alt text,
   warning/error/include controls and supported raw-output modes with sanitization.
   Add rich R data-frame tables and inline language expressions in document order.
   Keep execution defaults, skipped cells, and error continuation explicit. Compare
   supported cases against pinned Quarto/knitr/Jupyter reference outputs; full knitr
   rendering is a separate native-runtime target.
2. **FILE-1 — project inputs (L):** introduce an explicit manifest of user-selected
   files for Beancount includes, cross-file Org tables, and notebook data. Resolve
   only supplied files, detect cycles, and bound aggregate size/depth. Version the
   bundle/share representation while preserving single-document links and existing
   CID precedence. Never infer access to arbitrary local files from an include.
3. **OFFLINE-1 — optional scientific runtimes (L):** investigate self-hosting pinned,
   verified Python/R runtime assets and an explicit package set in a separate
   opt-in download. Measure transfer size, startup, storage, and memory first.
   Test fresh offline execution, interrupted installs, eviction, updates, and
   removal in all browsers. Arbitrary external packages/data remain network inputs.
4. **RUN-1 — explicit run/session controls (L):** keep fresh-per-render execution as
   the default. Evaluate manual Run/Run all and optional per-document live sessions
   for long computations. Isolate documents, show stale output, and verify cancel,
   restart, and full replay. Any Python/R exchange must use explicit typed data and
   defined ordering; shared implicit variable state is not assumed to be an upstream
   compatibility requirement.
5. **OJS-1 — reactive cells and widgets (L):** time-box an upstream-compatible
   Observable runtime experiment with isolated execution and a bounded output
   protocol. Use a separate sandbox for interactive content; never grant widgets
   access to editor storage or insert unsanitized HTML into the editor document.
   Prove cleanup, network behavior, and replay before enabling the feature.
6. **UI-1 — source-backed editing tools (L):** evaluate task toggles, Org recalculation
   application, Hurmet table/drawing controls, and a dedicated REPL as separate
   opt-in tools. Changes must round-trip through source, undo, URL/HashBin, and
   reload. They do not replace the reproducible source editor or turn Plain text
   into a markup/calculation format.

Browser package, memory, and storage limits cannot be made unbounded. Publish a
measured support matrix and a usable alternative for unsupported cases rather
than simply increasing global timeouts or hiding failed imports.

### Phase 16 — P3: a route to full native upstream behavior (L)

Some remaining gaps require applications or runtimes absent from this browser
build: full Quarto/Pandoc and native packages, Julia kernels, arbitrary Emacs Lisp,
Beancount plugins, desktop filesystem operations, or complete TeX document rendering.

Design an optional **local companion execution service** first. It would run pinned
upstream tools against an explicitly supplied project, return diagnostics and
artifacts through the existing document interface, and support cancellation and
resource limits. The static GitHub Pages editor remains independently usable.
Authenticated origin-bound communication and isolated job directories are part of
the design, not an assumption that a web document may execute desktop commands.

This milestone requires a separate decision on installation, supported platforms,
distribution/licenses, and execution trust before implementation. A hosted service
is a further hosting, cost, and data-handling decision, not an implicit dependency.
Closed Calca functionality still needs independently verified compatible behavior;
a generic native backend does not provide access to Calca's proprietary engine.

Done when: each native-only target either works against its pinned upstream tool
with reference fixtures and an end-to-end project round-trip, or remains explicitly
open with its required architecture decision. An unbuilt companion is not a fix.
